# RL-05 — idle reflection contract

The existing Herdr healer tick may queue a CoS-facing reflection after **600 seconds of observed stable idle/done**, separate from the existing recovery interval. No additional scheduler, timer process, actor creation, or recovery replay. The watchdog may notify only the registered CoS; it never assigns or sends the reflection prompt to a worker. Observation and queue updates use the existing `healer.lock` and goal registry CAS/persistence. The first eligible watchdog tick at or after 600 seconds may queue it; this is not a real-time deadline. Ordinary ticks are 30 seconds apart; a sampling gap over 45 seconds, failed probe, lock contention, hold, or changed turn/status report resets unproven time. Restart also discards unproven elapsed idle but preserves one-per-identity dedup in `runtime_reflections`.

## Opt-in registration

Add `reflection_bindings` to the existing `goals/*.json`. Each binding is `{participant_id, assignment_id, herdr:{terminal_id,created_ms}, turn, stood_down:false, paused:false, held:false, evidence:{name,path,sha256}, task_id?}`. One current binding per participant/generation. IDs and local handles must be exact: assignment is a canonical existing lowercase 32- or 64-hex ID; no receipt or name inference. The evidence is a hashed, nonempty JSON observation `{project_id,participant_id,assignment_id,herdr,turn,state:"settled"}` binding the original completion. It is supplied and authenticated by the controller; the runtime independently checks current Core `get --json` reports the same `address`, `created_ms`, `turn` and live `reported:true` with `status.state` idle/done and stable `status_ms`, without an owner-hold screen marker. Root/CoS and nested roles use the same logic.

V2 identities come from graph participants; optional `task_id` pins the latest settled, valid graph attempt to the binding (required when the assignment is in that graph). Explicit standalone bindings cover registered external assignments, e.g. a coordinator's own assignment. Legacy opt-in additionally requires explicit `reflection_project_id`; bind by existing supervisor/worker address and generation, with `participant_id` equal to its address. Old goals/receipts are not rewritten or inferred. Reflections yield to unresolved recovery of that work; legacy reflection yields while its goal remains under recovery/closeout. Held, paused, stood-down, unobserved, working, incomplete/mismatched evidence, or active conflicting attempt does not accumulate idle time. Duplicate canonical assignment bindings or the same physical generation and turn claimed by multiple projects are blocked rather than guessed.

## CoS route and actor recording

The watchdog appends one `runtime_reflections[reflection_id]` row containing bound project/participant/assignment/Herdr/turn, `reflection_id` (SHA-256 of the canonical JSON assignment + generation + turn), `stable_seconds`, `subject_evidence`, `requested`, `state:"coordinator_review_required"`, and `scope:{kind:"self-reflection-only",participant_id,assignment_id,turn}`. After durable admission, the watchdog can notify only registered CoS through `herdr-core send --json --if idle`, with the same reflection ID, private durable one-shot `notification` intent and exact returned turn or uncertain state. If CoS cannot safely receive the notification, the row stays queued. `herdr-idle-healer.sh reflections GOAL.json` lists the queue from registered CoS context. `herdr-idle-healer.sh reflection-route GOAL.json REFLECTION_ID` requires that same actor and admission. It records a one-shot `handoff` (reflection ID, handoff ID and original participant/handle/scope); for a worker it sends only the bounded reflection prompt via `--if idle`, while for a CoS reflection it self-routes without a second send. A `done` target is not sendable until actually `idle`. Intent survives failures and is never automatically replayed, including interrupted calls or ambiguous Core results. `herdr-idle-healer.sh reflection-record GOAL.json REFLECTION_ID --proof-file FILE` requires that routed handoff and records `state:"recorded", recorded_by, result` only as the original registered participant via exact `HC_TERMINAL_ID` plus current generation. Proof is `{reflection_id,handoff_id,project_id,participant_id,assignment_id,herdr,turn,worked,failed,root_cause_or_limits,carry_forward,evidence:[{name,path,sha256}]}`. All prose fields are nonblank; limits/no observed failure must be stated truthfully. Evidence artifacts are hashed and read, and original binding, holds and ownership rechecked before persistence. Original turn stays the reflection subject even if actor uses a later turn for recording. The queue and result remain in the same goal ledger.

After either send intent is persisted, the sender rechecks the ledger, existing ownership/recovery gates, both registered terminal generations and screen holds, the exact settled subject turn and the bound proof bytes. Worker route also rechecks CoS actor context. If these checks fail, a durable `blocked_before_send` intent is not replayed; failure after invoking transport remains `uncertain`. A compare-and-persist conflict leaves the already-durable intent rather than authorizing a retry. This is a sampled pre-send check, not an atomic hold+send guarantee: Core's conditional send only guards recipient idle, not screen holds, proof bytes or terminal generation.

Only registered CoS graph/CLI paths are covered. Controller must preserve canonical bindings and serialize lifecycle/hold/stand-down updates under the existing lock; this does not infer raw Desktop stand-down or authenticate a same-UID process forging its launch environment. This candidate is not installed or run on the active team. Notification is not authorization to act; only the supported actor-bound CoS command may route a reflection. Supported local transport cannot force an unavailable target or reconcile an uncertain delivery automatically. Automatic delivery to a terminal that remains `done` is not implemented: the installed conditional send does not admit `done`. Such a row stays pending until an actually idle observation or safe explicit CoS self-route; there is no force, unconditional send, or status-conversion fallback. Missing explicit registration or authoritative turn evidence fails closed.
